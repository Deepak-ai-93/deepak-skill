# skill: mcp-agent-builder

**Name:** MCP + AI Agent Builder — the full path from idea to working server in any IDE/CLI
**Description:** Takes an "I want an agent that can [do X]" request and produces the **full build path** as a pack: a **discovery interview** (what it connects to, who uses it, action surface, auth, deployment target) → **`mcp-prd.md`** (problem, users, features as tools/resources/prompts, auth, non-goals, success metrics) → **`mcp-architecture.md`** (deployment model, transport, auth flow, error handling, security, testing) → **`server/`** — a **runnable MCP server scaffold** generated by `scaffold-server.mjs` from `mcp-plan.json` (real `@modelcontextprotocol/sdk` code, zero secrets, connect configs for every IDE/CLI) → **`agent-design.md`** (the system prompt + tool wiring + guardrails that turn the server into an agent capability) → **`ide-cli-matrix.md`** (connect it in Claude Code, Cursor, Codex CLI, Gemini CLI, OpenCode, Cline, Windsurf, VS Code, Zed) → **`mcp-audit.md`** (the audit harness output). Built for any agentic CLI — the same skill works in Claude Code, Cursor, Codex, Gemini CLI, and 70+ more.

---

## The quality bar (non-negotiable — read before anything else)

| Rail | Rule |
|---|---|
| **Discovery before code (the #1 rail)** | Never scaffold before the discovery interview (`templates/mcp-discovery.md`). The deployment model, auth, and tool surface are decided in discovery — guessing them silently produces a server nobody can run. |
| **PRD first, architecture second** | `mcp-prd.md` locks the WHAT (problem, users, tools/resources/prompts, auth, non-goals, metrics) before `mcp-architecture.md` locks the HOW. A tool not in the PRD is not built. |
| **One deployment model, honestly chosen** | Pick exactly ONE of stdio / remote HTTP / MCPB from discovery (tables in `templates/architecture-template.md`), and the architecture's transport + auth flow must match it. No generic copy-pasted architecture. |
| **Scaffold is real and runnable** | `scaffold-server.mjs` generates a real server: `package.json` with `@modelcontextprotocol/sdk`, `src/index.mjs` with ONE handler per plan tool, a README with run + connect steps, per-IDE configs, and a `.env.example` — never real secrets. `npm install && npm start` works out of the box (mock mode). |
| **Agent wiring ships with the server** | `agent-design.md` (system prompt + tool wiring + guardrails) and `ide-cli-matrix.md` (≥ 3 IDEs/CLIs with exact connect commands) are part of the deliverable — a server nobody can connect is not done. |
| **Audited before delivery (the harness)** | Stage 7 is a harness, never a self-check: `audit-mcp.mjs` runs the automated checks (PRD, architecture, scaffold, agent wiring, IDE matrix, secrets) → a FRESH mcp-auditor subagent scores the pack (/50, ≥ 35 = worth shipping) → fix loop until signed **PASS** in `mcp-audit.md`. |

## Workflow (7 stages)

### Stage 1 — Discovery interview → `mcp-discovery.md`
Run the questionnaire from `templates/mcp-discovery.md` — at most one round of questions, then defaults with a **Decisions** note. Extract:

| Question | Decides |
|---|---|
| What does it connect to? | cloud API · local process · filesystem · hardware |
| Who will use it? | just you · your team · anyone (publish to the MCP Registry) |
| Action surface size | a handful of operations vs wrapping a large API |
| Upstream auth | none · API key · OAuth 2.0 |
| Deployment target | stdio (local IDE/CLI) · remote HTTP · MCPB bundle |
| Which IDEs/CLIs must connect | Claude Code · Cursor · Codex · Gemini CLI · OpenCode · Cline · … |

### Stage 2 — Write the PRD → `mcp-prd.md`
Fill `templates/prd-template.md`: **Problem** (one paragraph + the trigger scenario) · **Users** · **Features** — every capability as a **tool** (name, description, params), **resource**, or **prompt** · **Auth + compliance** (credential flow, what's stored, data retention) · **Non-goals** (what this server explicitly does NOT do) · **Success metrics** (e.g. "agent completes task X without human help"). A feature that isn't listed here is out of scope.

### Stage 3 — Write the architecture → `mcp-architecture.md`
Fill `templates/architecture-template.md` with ONE locked **deployment model** (stdio / remote HTTP / MCPB) + **stack** (Node `@modelcontextprotocol/sdk` default, Python FastMCP alternative) · **transport** (stdio vs streamable HTTP — must match the deployment model) · **tool design** (one idea per tool, zod schemas, error returns) · **auth flow** (where credentials live, how tokens are stored/refreshed) · **error handling** (tool errors as structured content, never crashes) · **security** (no secrets in code, input validation, rate limits) · **testing** (MCP Inspector + a mock-mode smoke test).

### Stage 4 — Write the plan + scaffold the server → `server/` (automated)
Write `mcp-plan.json` from the PRD (name, version, description, deployment, auth, tools with params), then:
```bash
node scripts/scaffold-server.mjs --plan mcp-plan.json --out server
```
The script **validates** (name/description present · deployment in stdio/remote-http/mcpb · auth mode known · ≥ 1 tool with a name + description · param types string/number/boolean) and **exits 1 on any FAIL**, then generates: `package.json` (SDK + zod deps, `npm start`) · `src/index.mjs` (a real `McpServer` with ONE handler per plan tool — mock mode that echoes args, `// TODO` markers for the real integration) · `README.md` (run + connect per IDE) · `config/` (Claude Code, Cursor, Codex, Gemini, OpenCode snippets) · `.env.example` (auth vars, never values).

### Stage 5 — Write the agent wiring → `agent-design.md` + `ide-cli-matrix.md`
- `agent-design.md` — the system prompt that teaches the agent what the server can do + when to call which tool, tool-use patterns (call, read result, retry), and guardrails (never send secrets, confirm destructive actions).
- `ide-cli-matrix.md` — exact connect commands for every IDE/CLI the user named (from `templates/ide-cli-matrix.md`): `claude mcp add`, `.cursor/mcp.json`, Codex `config.toml`, `gemini mcp`, OpenCode, Cline, Windsurf, VS Code, Zed.

### Stage 6 — Approval gate
Show the user: **PRD + architecture + scaffold summary + agent design**. They say **approve / edit / reject** — no audit, no delivery before approval. Edits go back to the affected stage and re-run the scripts.

### Stage 7 — Audit harness (automated checks + mcp-auditor subagent, before delivery)
**Step 7a — run the automated audit harness:**
```bash
node scripts/audit-mcp.mjs --pack <mcp-folder> --out mcp-audit.md
```
`audit-mcp.mjs` scans the pack and checks everything a script can: `mcp-prd.md` (problem/users/features/auth/non-goals/metrics sections), `mcp-architecture.md` (deployment model, transport, auth flow, error handling, security, testing), the scaffold (`package.json` with the SDK, `src/index.mjs` with a handler per plan tool, README with connect steps, `.env.example` present and **no real secrets**), `agent-design.md` (system prompt, tool wiring, guardrails), and `ide-cli-matrix.md` (≥ 3 IDEs/CLIs). Writes `mcp-audit.md` (automated verdicts + scorecard scaffold). **Exit 1 on any FAIL.**

**Step 7b — spawn the mcp-auditor subagent** — a FRESH subagent (never self-audit) with the exact brief from `templates/mcp-auditor-brief.md`: reads `mcp-audit.md` + all pack files, completes the **MCP-pack scorecard** (10 criteria, /50 — **≥ 35 = worth shipping**, with verdict bands), makes the creative judgment calls the script can't (tool naming/description quality, auth-flow soundness, scaffold runnability, agent-prompt usefulness), and signs **PASS / FIX NEEDED** with per-file fixes.

**Step 7c — fix loop.** Any FAIL (or an auditor-flagged WARN) → fix the file → re-run `scaffold-server.mjs` (if the plan changed) + `audit-mcp.mjs` → re-submit to a fresh auditor. **Nothing is delivered until the auditor signs off PASS.** The `mcp-audit.md` ships with the pack.

## Production checklist

- [ ] Discovery interview done → `mcp-discovery.md`; deployment model + auth + IDE/CLI list locked
- [ ] `mcp-prd.md`: problem, users, tools/resources/prompts, auth + compliance, non-goals, success metrics
- [ ] `mcp-architecture.md`: ONE deployment model, transport matches it, auth flow, error handling, security, testing
- [ ] `mcp-plan.json` matches the PRD (every tool in the PRD is in the plan)
- [ ] `scaffold-server.mjs` ran clean (exit 0) → `server/` with SDK dep + a handler per tool + README + configs + `.env.example`
- [ ] No real secrets anywhere (`.env.example` only)
- [ ] `agent-design.md`: system prompt + tool wiring + guardrails
- [ ] `ide-cli-matrix.md`: exact connect commands for ≥ 3 IDEs/CLIs the user named
- [ ] Approval gate: user approved PRD + architecture + scaffold before delivery
- [ ] **Audit harness run:** `audit-mcp.mjs` → automated checks (PRD, architecture, scaffold, agent wiring, IDE matrix, secrets) — exit 0
- [ ] **MCP-auditor subagent** (fresh eyes) completed the MCP-pack scorecard (/50 ≥ 35) and signed **PASS / FIX NEEDED** in `mcp-audit.md`
- [ ] Delivery: `mcp-discovery.md` + `mcp-prd.md` + `mcp-architecture.md` + `mcp-plan.json` + `server/` + `agent-design.md` + `ide-cli-matrix.md` + `mcp-audit.md`
