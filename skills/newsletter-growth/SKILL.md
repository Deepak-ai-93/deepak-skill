# skill: newsletter-growth

**Name:** Newsletter Growth — story-first issues + the growth engine around them
**Description:** Turns a week's idea into a **ready-to-send editorial newsletter pack**: `issue.md` (subject line + story-first issue — open loop → stakes → payoff → value receipts → ONE CTA → growth plug, every constraint enforced by `issue-writer.mjs`) + `growth-plan.md` (welcome sequence, referral loop, cross-promos, analytics review) + `newsletter-audit.md` (the audit harness output). Editorial + growth — distinct from `email-marketing`, which builds transactional ESP campaigns.

---

## Storytelling + addiction rails (the universal contract — read before anything else)

Every deliverable this skill produces must tell **ONE micro-story** and engineer **rewatch**. These rails are the SAME contract every video/image skill in this repo follows — apply them to every beat, scene, slide, shot or clip before it ships.

**Applied to newsletters:** the issue IS the micro-story — the subject line + first line open the loop ("what happened next?"), the middle raises the stakes (the twist, the mistake, the number), the payoff delivers the lesson, and the ending closes with ONE ask + a growth plug. The open loop is what gets the email opened and read to the bottom; the growth plug (referral/forward) is what turns a reader into a subscriber.

### The story spine (all four beats, always)

| Beat | Rule |
|---|---|
| **Open loop (hook, 0–3s)** | The first thing the viewer sees — first frame, cover slide, first scene — opens an unresolved question, tension or promise the brain must see closed. No intro, no logo, no "hey guys". |
| **Rising tension** | Every beat after the hook escalates: new stakes, a twist, a pattern interrupt, an "and then…". Each beat either raises the question or raises the stakes — never just fills time. |
| **Payoff** | The open loop closes in the final seconds with the "aha" the hook promised. A loop opened and never closed kills trust and rewatch. |
| **Loop ending** | The last frame mirrors or seeds the first (rewatch counts as a second view) or chains into the next post ("Part 2", "Follow for part 2", "Save this"). |

### The addiction levers (use ≥3 per deliverable)

| Lever | Mechanism |
|---|---|
| **Curiosity gap** | The open loop the brain must close (Zeigarnik effect — unfinished tasks nag). |
| **Serialization / cliffhanger** | Cut before resolution; chain posts into a series so the audience returns for the next installment. |
| **Variable reward** | Reveal payoffs on a beat the viewer can't predict — countdowns, answer reveals, verdicts, twists. |
| **Pattern interrupt** | A scale pop, color flash or tempo break exactly where attention dips (the mid-video hump). |
| **Relatability / self-recognition** | "That's me" moments — the viewer watches to see their own life, then saves or shares it. |
| **Commitment bait** | Save / share / comment / "what's your #?" — an engaged viewer is a returning viewer. |

### The fluff rule

Every beat either **raises the question**, **raises the stakes**, or **pays off**. If a beat can be deleted without losing the story, delete it.

## The quality bar (non-negotiable — read before anything else)

| Rail | Rule |
|---|---|
| **Subject line earns the open (the #1 rail)** | The subject is ≤ 60 chars, uses ONE proven formula (curiosity / number / how-to / pain / story — from `templates/issue-template.md`), and matches the issue's promise exactly — no bait the issue doesn't pay off. |
| **Story-first issue** | The issue opens with a hook that opens a loop, raises stakes through the middle, pays off, then delivers value. Never starts with "Here's what I want to share with you". |
| **One CTA + one growth plug** | Exactly ONE primary CTA (reply, subscribe-forward, link click) and ONE growth plug (referral/forward ask) per issue. Two asks = no asks. |
| **Anti-fluff, receipts** | No fluff words (unlock, game-changer, elevate, …); specific beats generic — numbers, examples, named people. Every paragraph either informs, proves, or entertains. |
| **Growth plan ships with the issue** | Every pack includes `growth-plan.md` (welcome sequence, referral loop, cross-promos, analytics review) — the issue is the product, the plan is the growth. |
| **Audited before delivery (the harness)** | Stage 6 is a harness, never a self-check: `audit-newsletter.mjs` runs the automated checks (subject, story spine, anti-fluff, CTA/growth, word window, growth plan) → a FRESH newsletter-auditor subagent scores issue worthiness (/50, ≥ 35 = worth sending) → fix loop until signed **PASS** in `newsletter-audit.md`. |

## Workflow (6 stages)

### Stage 1 — Analyze the brief (ask ≤3 questions if vague)
Extract: **topic** · **audience** · **voice** (the writer's real voice — newsletters live or die on this) · **cadence** (weekly default) · **goal** (opens / replies / forwards / subscribers) · **the ONE CTA**. Lock the goal — it decides the CTA and the growth plug.

### Stage 2 — Pick the story + subject formula
What happened this week: the story that proves the point (a win, a mistake, a client, a number). Then pick the subject formula from `templates/issue-template.md` that matches the story's promise.

### Stage 3 — Write the issue plan → `issue-plan.json`
The creative contract the script enforces:
- `topic`, `audience`, `voice`, `goal`, `cta`, `growthPlug`
- `subject` + `subjectFormula` (≤ 60 chars, one formula)
- `story`: `hook` (opens a loop) → `conflict` (rising stakes) → `payoff` (the aha)
- `value[]` — 2–4 concrete receipts (numbers, examples, names) that prove the payoff

### Stage 4 — Assemble + validate → `issue.md` (automated, exit 1 on bad plans)
```bash
node scripts/issue-writer.mjs --plan issue-plan.json --out issue.md
```
The script validates: subject ≤ 60 chars + formula · story has hook/conflict/payoff · ≥ 2 value items · CTA + growth plug present · anti-fluff blocklist. **Exits 1 on any FAIL** and writes nothing. On clean it writes the polished `issue.md` — subject, story-first sections, value receipts, one ask, growth plug, word count + read time.

### Stage 5 — Write `growth-plan.md`
The welcome sequence (first 5 emails), the referral loop, cross-promos, and the analytics review — from `templates/growth-tactics.md`. The issue gets the opens; the plan compounds them into subscribers.

### Stage 6 — Audit harness (automated checks + newsletter-auditor subagent, before delivery)
**Step 6a — run the automated audit harness:**
```bash
node scripts/audit-newsletter.mjs --pack <newsletter-folder> --out newsletter-audit.md
```
`audit-newsletter.mjs` scans the pack and checks everything a script can: issue.md (subject ≤ 60 chars + formula, story-spine sections — hook/stakes/payoff present, ≥ 2 value bullets, ONE CTA, growth plug, word window 350–900, anti-fluff blocklist, specificity — numbers/receipts present) and growth-plan.md presence. Writes `newsletter-audit.md` (automated verdicts + scorecard scaffold). **Exit 1 on any FAIL.**

**Step 6b — spawn the newsletter-auditor subagent** — a FRESH subagent (never self-audit) with the exact brief from `templates/newsletter-auditor-brief.md`: reads `newsletter-audit.md` + all pack files, completes the **issue-worthiness scorecard** (10 criteria, /50 — **≥ 35 = worth sending**, with verdict bands), makes the creative judgment calls the script can't (subject pull, story believability, CTA clarity, voice consistency), and signs **PASS / FIX NEEDED** with per-section fixes.

**Step 6c — fix loop.** Any FAIL (or an auditor-flagged WARN) → fix `issue-plan.json` → re-run `issue-writer.mjs` + `audit-newsletter.mjs` → re-submit to a fresh auditor. **Nothing is delivered until the auditor signs off PASS.** The `newsletter-audit.md` ships with the pack.

## Production checklist

- [ ] Subject ≤ 60 chars, one formula, matches the issue's promise exactly
- [ ] Story-first issue: hook opens a loop → stakes → payoff → value receipts
- [ ] Story spine complete: open loop → rising tension → payoff → loop ending; no beat survives the fluff rule
- [ ] ≥3 addiction levers used (curiosity gap · serialization · variable reward · pattern interrupt · relatability · commitment bait)
- [ ] ONE CTA + ONE growth plug (never two asks)
- [ ] Anti-fluff; numbers/specifics beat adjectives
- [ ] `issue-writer.mjs` ran clean (exit 0) → `issue.md`
- [ ] `growth-plan.md` written: welcome sequence, referral loop, cross-promos, analytics review
- [ ] **Audit harness run:** `audit-newsletter.mjs` → automated checks (subject, story spine, anti-fluff, CTA/growth, word window, growth plan) — exit 0
- [ ] **Newsletter-auditor subagent** (fresh eyes) completed the issue-worthiness scorecard (/50 ≥ 35) and signed **PASS / FIX NEEDED** in `newsletter-audit.md`
- [ ] Delivery: `issue.md` + `growth-plan.md` + `newsletter-audit.md`
